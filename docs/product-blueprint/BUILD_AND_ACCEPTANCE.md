# 构建与验收蓝图｜个人 AI 作品集与网页版简历

- Blueprint: v1.0
- Last updated: 2026-08-29
- Status: Ready
- Authority: 本文件是纵向切片、`ACT-*` 追踪、测试证据、阶段门禁、完成定义与停止升级条件的唯一权威来源。

## 1. 交付结果与不可中断承诺

最终结果不是“有七个导航入口”，而是七个可独立访问、内容结构完整、交互可用、视觉世界完整并通过共同质量门槛的页面族。

- **第一批**：Hero（`/`）、Projects（列表与详情）、About/Resume、Honors。
- **第二批**：Journal（列表与正文）、Videos、Photos。
- 第一批全部通过批次门禁后，开发流程**立即自动进入第二批**，不等待用户再次说“继续”。
- 第一批未过门禁时先修复阻塞；不得以“第二批入口已出现”“Coming soon”“空白模板”作为继续或完成证据。
- 允许真实素材暂缺时使用 Registry 中明确标注的 `placeholder` / `ai-generated`，但页面结构、核心状态、可访问路径、响应式、交互与验收必须完整；素材占位不是页面体验占位。
- 第二批只有在 Journal、Videos、Photos 各自的独立视觉世界及核心旅程均完成后才能宣告全站完成。

## 2. 冻结边界

- 系统采用 `SYSTEM_BLUEPRINT.md` 的静态优先 Next.js App Router + TypeScript 倾向、TS/MDX 内容、Asset/Link Registry 与路由隔离方案。
- 视觉与交互实现必须遵守 `EXPERIENCE_BLUEPRINT.md`，本文件不重复定义页面艺术方向。
- 当前不做账号、后端、数据库、站内联系表单、远程 CMS、评论或追踪 SDK。
- `OPEN-004` 使用安全默认：真实个人资料接入前保持显式占位；`OPEN-005` 延后到发布配置，不阻塞本地切片。
- 实现发现规格冲突时先停止受影响切片并回写蓝图；不得在代码中默选新的业务规则。

| 顺序 | 切片 | 用户价值与范围 | 依赖 / ACT | 完成证据 | 非范围 | 停止/升级条件 |

### 4.1 自动进入第二批的机械规则

1. VS-05 的所有第一批门禁为 Pass。
2. 将 ACT-001 至 ACT-005、ACT-009（第一批覆盖部分）更新为 Verified；ACT-010 至少完成占位/真实链接规则验证。
3. 同一工作分支中立即开始 VS-06；无需确认、不开新范围讨论。
4. Journal 完成后可在没有文件冲突时并行 VS-07/VS-08，但各自使用独立 feature/route 边界和独立审查者。
5. 第二批任一页面只有入口或骨架时保持 Planned/Implemented，绝不能标 Verified。

## 5. 行为验收场景

| 场景 | Given | When | Then | 恢复/边界 | 层级 |
|---|---|---|---|---|---|
| 首页到项目闭环 | 生产构建且有一个已发布示例 | 键盘从首页进入项目并打开详情 | URL、标题、正文、返回路径和素材披露正确 | 禁 JS 时普通链接仍成立 | E2E + manual |
| 项目筛选无结果 | 存在多个筛选项 | 组合出零结果 | 说明当前条件并可一键清除，原集合恢复 | 不丢焦点、不报错 | integration + E2E |
| 假链接防线 | Link 为 unavailable 或内容误填 `#` | 构建/渲染 | unavailable 为非交互；假 href 令校验失败 | 不发布坏制品 | unit + build |
| 素材披露 | Asset 分别处于三种状态 | 打开引用该资产的页面 | placeholder/AI 状态有一致披露；final 按 provenance 处理 | 缺披露构建失败 | unit + E2E |
| 打印简历 | About 已加载 | 打印/保存 PDF | 关键信息完整、顺序清楚、无导航遮挡和不可读背景 | 缺真实内容仍明确为占位 | visual + manual |
| 荣誉隐私 | Honor 引用 review-required 证据 | 运行生产构建 | 构建失败并定位 Honor/Asset | 使用审核后的遮挡版或继续占位 | build |
| 文章路由 | 一篇 published 和一篇 draft | 访问目录、正文和未知 slug | 只公开 published；未知 slug 404；draft 不进 sitemap | MDX 不支持组件时报构建错 | build + E2E |
| 视频失败 | 视频源不可播放 | 尝试播放 | 保留 poster、说明和文字稿/真实来源 | 无源时从未出现假播放按钮 | integration + manual |
| 图片失败 | Photo 源加载失败 | 浏览照片页 | 占位区域保持尺寸并显示说明 | 仍能继续浏览/关闭增强视图 | integration + E2E |
| 减弱动效 | 系统开启 reduced motion | 访问并操作所有世界 | 核心内容即时可用，无非必要大幅位移/自动播放 | 与普通模式信息等价 | E2E + manual |
| 一致导航 | 任意顶级路由 | 依次 Tab/打开导航 | 项目相对顺序、名称和目标一致 | 外观可不同但语义不变 | E2E + a11y |
| 404 恢复 | 请求未知页面/slug | 页面返回 | 明确 404，提供首页与相关展区真实入口 | 不静默跳首页 | E2E |

## 6. 测试与验证命令契约

当前尚未脚手架化，因此**不伪造已经可运行的命令**。VS-01 创建脚手架并锁定包管理器后，必须在 `package.json` 落地以下稳定 script 名称；把下表 `<pm>` 替换为 lockfile 对应命令，并将真实输出链接回 ACT 矩阵。

| 目的 | 脚手架后必须可运行的命令 | 阻塞范围 |
|---|---|---|
| 类型 | `<pm> run typecheck` | 任一切片合并 |
| 代码规范 | `<pm> run lint` | 任一切片合并 |
| 内容/Registry | `<pm> run validate:content` | 任一页面发布 |
| 单元/集成 | `<pm> run test` | 任一切片合并 |
| 浏览器旅程 | `<pm> run test:e2e` | 批次门禁 |
| 生产静态构建 | `<pm> run build` | 任一切片完成 |
| 内外链 | `<pm> run check:links` | 批次门禁/发布 |
| 自动无障碍 | `<pm> run audit:a11y` | 批次门禁/发布 |
| 性能预算 | `<pm> run audit:perf` | 批次门禁/发布 |
| 路由 bundle | `<pm> run analyze` | 新增重型依赖/发布 |
| 全部门禁 | `<pm> run verify` | `typecheck + lint + validate:content + test + build`；CI 必跑 |

浏览器 E2E 默认采用 Playwright 或脚手架时等价的跨浏览器工具；自动 a11y 可使用 axe 等规则引擎，但不能代替键盘、屏幕缩放、字幕、打印和真实设备人工检查。

## 7. 批次与最终质量门禁

### 7.1 第一批门禁（VS-05）

- Hero、Projects（含详情）、About/Resume、Honors 的正常、空、错误、占位/AI/final 状态均完整。
- 四个页面族分别符合 Experience 蓝图的视觉世界验收；共享导航、内容 schema 与素材披露没有分叉。
- ACT-001 至 ACT-005 已 Verified；ACT-009 在第一批全路由 Verified；ACT-010 的 unavailable/active 规则 Verified。
- `verify`、E2E、链接、自动 a11y、性能、SEO 和第一批浏览器矩阵全部 Pass。
- 通过后自动进入 VS-06；不能以“先给用户看看”暂停第二批承诺。

### 7.2 最终门禁（VS-09）

- ACT-001 至 ACT-010 全部 Verified，七个世界都不是骨架或入口占位。
- WCAG 2.2 AA：0 个自动化严重/关键问题；全站键盘路径、跳过入口、焦点可见且不遮挡、200% 缩放/320px 回流、触控替代、reduced motion、alt、字幕/文字稿人工通过。
- 性能：按 `SYSTEM_BLUEPRINT.md` 的 CWV、Lighthouse、JS、图片预算验证；生产构建每个顶级路由至少 3 次取中位数，报告留档。
- SEO：唯一 title/description/canonical、静态可抓取正文、404、sitemap/robots、OG、结构化数据真实性、草稿/隐私素材不泄露全部通过。
- 浏览器：Chrome/Edge/Firefox/Safari 当前与前一主要版本；Windows、macOS Safari、iOS Safari、Android Chrome 的核心旅程通过。视觉允许渐进差异，功能和信息不得降级。
- 静态制品可部署、无秘密、可回滚到上一份验证制品；部署平台未定时只能宣告“开发完成/可发布”，不能宣告“已上线”。

## 8. Release blockers

以下任一存在即禁止批次完成或公开发布：

- 核心页面只有导航入口、Coming soon、空模板或复制其他页面视觉后未完成独立世界。
- 未标注的 placeholder/AI 素材、虚构事实、`#`/空 href/假域名、不可播放却可点击的视频。
- 键盘无法到达/退出，焦点被遮挡，关键内容只能拖拽/悬停/Canvas 访问，reduced motion 无等价路径。
- 发布视频缺字幕/文字稿；图片/证书隐私仍为 `review-required`；真实联系方式未经用户批准。
- 内容、类型、测试、生产构建、链接、a11y、性能或目标浏览器关键旅程失败。
- 页面世界的全局副作用污染其他路由，或重型依赖进入所有页面 bundle。
- 引入后端、远程 CMS、追踪或第三方嵌入但未重开系统/隐私契约。

## 9. 停止升级条件

实现 Agent 在以下情况停止当前切片并升级到蓝图/用户决定，不继续扩范围：

1. 必须公开真实联系方式、奖状、人脸、学校敏感信息，但 `OPEN-004` 未关闭。
2. 需求需要数据写入、账号、API、数据库、远程 CMS、分析/追踪或有 Cookie 的第三方服务。
3. Next 静态导出无法承接核心路由，或解决方案依赖服务器能力；先提供失败证据与 Astro/Node 部署对比。
4. 为实现艺术方向必须违反 WCAG 核心路径、性能预算或一致导航，且无等价安全路径。
5. 同一事实在 Product/Experience/System 蓝图中矛盾，或实现需要猜测荣誉、项目结果、内容状态。
6. 新依赖让路由 bundle 超预算，且无法按路由隔离；必须先给出 bundle 证据、轻量替代和收益。
7. 同一类失败连续修复两次仍复现，先缩小复现和更新 ACT 证据，不用更多特效掩盖。

停止升级只暂停受影响范围；不相关切片可继续。不得把缺素材当作停止整个项目的理由，使用明确状态的占位即可完成体验。

## 10. 三重审查与 Ready 证据

| 审查/门禁 | 状态 | 证据与结论 |
|---|---|---|
| Skeptic Review | Pass | 最大失败点（页面分叉、性能、假内容、隐私、第二批烂尾）均有 Registry、路由隔离、批次门禁和 blocker 承接 |
| Simplifier Review | Pass | 删除后台、数据库、表单、远程 CMS、评论、追踪和预建平台层；保留七页是用户明确范围，不能 Remove-One |
| Blind-Handoff Review | Pass | 新 Agent 可从 VS-01 开始，知道 ACT、内容边界、验证脚本名称、批次推进和停止条件，无需重问关键范围 |
| Product/UX/Visual | Pass | 用户、两批范围与七个独立世界已冻结；体验细节由对应权威蓝图承接 |
| Frontend–Backend Integrity | Pass | 首版全部 local-only/真实外链，无伪 API 或未定义后端 |
| Architecture Fitness | Pass | 静态优先、统一 schema、Registry、路由拆包与迁移边界明确 |
| Testability / Agent Handoff | Pass | ACT 矩阵、纵向切片、脚手架后命令契约、门禁与阻塞条件齐全 |
| Security / Operations | Conditional | `OPEN-004/005` 使用安全默认；不阻塞本地开发，但真实资料接入与公开发布前必须关闭对应门禁 |
