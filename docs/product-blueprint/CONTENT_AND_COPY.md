# 内容与文案蓝图｜个人 AI 作品集与网页版简历

- **Blueprint version:** 1.0
- **Last updated:** 2026-08-29
- **Status:** Ready / Approved
- **Authority:** 本文件是内容类型、字段语义、来源状态、AI 占位真实性、品牌语言与文案规则的单一事实来源。页面范围与业务动作见 `PRODUCT_BLUEPRINT.md`；不在此规定页面布局、动效或技术存储方式。

## 1. 内容原则

1. **先像本人，再服务观看者。** 内容首先准确表达本人，其次制造师友愿意讨论的发现，最后让专业访客高效验证能力。
2. **证据优先于形容词。** 用项目过程、选择、结果、荣誉来源和持续记录体现能力，不用空泛的“优秀”“精通”“顶尖”。
3. **允许未完成，不允许假装完成。** 占位和 AI 生成内容可以支持视觉开发，但必须清楚说明其状态和替换目标。
4. **一条内容只维护一个事实。** 同一项目、荣誉或经历的名称、日期与状态来自其主条目；页面只引用，不另写一份相互漂移的副本。
5. **差异化世界，共用一种人格。** 各世界可以改变叙事形式，但不得把同一个人写成七种互相矛盾的口吻。

## 2. 内容模型

### 2.1 共享字段与生命周期

除单例身份信息外，可发布条目共用以下语义字段：

- `id / slug`：稳定身份与可分享地址；标题变化不应破坏既有链接。
- `title / summary`：标题和可独立理解的短摘要。
- `publishedAt / updatedAt`：仅在日期真实可确认时填写；未知不得猜测。
- `tags / relatedIds`：用于分类与关联探索，不作为关键词堆砌。
- `publication`：`draft → ready → published → archived`；归档不等于删除事实。
- `provenance`：`placeholder | ai-generated | final`；来源状态不得随发布状态自动升级。
- `owner / sourceNote`：谁提供、从何核验；最终内容必须可追溯到本人或明确的真实来源。

### 2.2 类型目录

| 内容类型 | 目的 | 必需字段 | 来源 / 所有者 | 生命周期 | 空状态 / 错误状态 |
|---|---|---|---|---|---|

| Project | 证明 AI 开发、创作、实验和解决问题的能力 | 标题、短述、类型、本人角色、问题、过程、关键选择、工具、结果、证据、封面资产、链接、状态 | 本人；结果和外链需核验 | 概念占位 → 制作中 → 可展示 → 持续迭代 → 归档 | 无真实项目时可展示“AI 概念案例”，必须可见标注；无外链时禁用动作而非填写假地址 |

## 3. AI 占位与真实性契约

### 3.1 三种唯一来源状态

| 状态 | 含义 | 可见表现 | 允许的动作 |
|---|---|---|---|
| `placeholder` | 仅用于预留结构、尺寸或内容位置，不声称是真实资料 | 靠近内容显示“占位内容 · 待本人替换”或该类型的等义明确标签 | 可浏览结构；外链、下载、联系和真实性证明动作保持禁用 |
| `ai-generated` | 使用 AI 生成的概念图、文案样例或演示素材 | 靠近素材显示“AI 生成概念示意 · 非真实作品/证书/照片”，详情可查看来源说明 | 可用于体验演示；不得作为个人真实经历、成果或荣誉证据 |
| `final` | 已由本人提供或确认，来源、使用权和隐私均完成检查 | 无需额外占位标签；必要时保留正常署名或来源 | 仅在链接也已验证时启用外部访问、下载或联系动作 |

状态升级必须经过人工确认，不能因文件名、上传完成、页面发布或视觉完成自动从 `placeholder/ai-generated` 变为 `final`。

### 3.2 不可违反的真实性规则

- 不生成看似真实的学校、机构、赛事、证书编号、印章、名次、客户、推荐语或项目数据。
- 不使用可点击的 `#`、示例域名、假邮箱或假社交账号模拟真实动作。
- AI 生成的人像、照片、奖状和界面截图必须在其最接近的可见上下文标注，不能只藏在页脚免责声明。
- “AI 辅助制作”与“AI 生成概念示意”必须区分：真实项目使用 AI 工具仍可为 `final`，前提是项目事实真实；虚构项目即使画面精致仍是 `ai-generated`。
- 真实证书与照片上线前必须完成隐私检查；姓名以外的证件号、学号、二维码、地址、电话等默认遮挡。
- 资产替换时保持稳定的内容身份与替代文本责任，避免真实素材到位后破坏链接或可访问性。

### 3.3 推荐可见标签

- `占位内容 · 待本人替换`
- `AI 生成概念示意 · 非真实项目`
- `AI 生成证书示意 · 非真实荣誉`
- `AI 概念影像 · 后续替换为本人素材`
- `真实链接待补充`
- `资料由本人确认于 YYYY-MM-DD`（仅在确实完成确认后使用）

## 4. 品牌人格翻译

### 4.1 核心人格句

**韧性驱动的数字探索者：把好奇变成作品，把挫折变成下一版。**

这句话是写作校准器，不要求机械重复在每个页面。品牌表达应让访客从内容证据中自然得出人格判断。

### 4.2 从人格词到可观察表达

| 用户原词 | 内容与语言中的翻译 | 应展示的证据 | 禁止滑向 |
|---|---|---|---|
| 百折不挠 | 坦然说明困难、失败、修正和再次尝试 | 版本演进、失败复盘、问题如何被解决 | 苦情叙事、空喊坚持 |
| 卧薪尝胆 | 用克制语气呈现长期积累、准备和延迟满足 | 时间线、持续学习、阶段目标与回看 | 复仇感、卖惨、过度宏大叙事 |
| 博闻多识、兴趣盎然 | 展示跨领域好奇心，以及知识如何发生连接 | 多类型项目、阅读/研究笔记、兴趣交叉成果 | 无边界罗列工具和热点名词 |
| 深思敏悟 | 说清为什么做、观察到了什么、下一次会如何选择 | 决策说明、洞察、复盘、观点文章 | 晦涩玄学、故作深沉 |
| 争强好胜 | 对品质和结果有高标准，愿意接受比较和验证 | 比赛、挑战、清楚目标、可核验成果 | 贬低他人、虚构排名、攻击性炫耀 |
| 思如泉涌 | 让创意充沛但经过组织，有灵感也有落地 | 实验队列、草图、概念到成品的路径 | 信息爆炸、每处都抢注意力 |
| 自信昂扬 | 使用直接的一人称、清楚动词和向前姿态 | 明确主张、主动 CTA、对作品边界诚实 | 无证据的自夸、绝对化承诺 |

### 4.3 总体语气

- **第一人称、主动、坦率。** “我做了 / 我选择 / 我学到”优于无主语的被动句。
- **昂扬但不膨胀。** 有锋芒，也承认边界、失败和仍在探索的部分。
- **聪明但不晦涩。** 复杂思考用具体例子说明，不用术语制造距离。
- **有趣但不油滑。** 页面命名和微文案可以有游戏感，事实与专业信息保持准确。
- **竞争心指向作品标准。** 强调“我想把它做到更好”，不通过贬低别人抬高自己。

## 5. 文案契约

### 5.1 术语

| 场景 | 优先使用 | 避免使用 |
|---|---|---|
| 项目 | 项目、实验、作品、版本、复盘 | 黑科技、颠覆、行业领先（无证据时） |
| 能力 | 我做过、我正在探索、在这些项目中使用 | 精通、全栈大神、专家（无充分证据时） |
| 荣誉 | 荣誉档案、比赛记录、里程碑、本人贡献 | 获奖无数、权威认证（来源不明时） |
| 经历 | 成长轨迹、在校经历、实践角色 | 完美履历、人生赢家 |
| 文章 | 随笔、复盘、方法、观察 | 深度干货（内容无法支撑时） |
| 视频 | 放映、观看、演示、影像记录 | 震撼大片、必看（泛化使用时） |
| 照片 | 照片墙、生活切片、阶段记录 | 私密照、偷拍等越界表达 |
| 未完成 | 待本人替换、正在整理、真实链接待补充 | 敬请期待（没有具体状态时）、假装可用的按钮 |

### 5.2 CTA 体系

CTA 必须说明动作结果，不使用只有“点击这里”“更多”的空泛标签。

| 目的 | 推荐 CTA | 使用条件 |
|---|---|---|
| 首页主动作 | `开始探索` | 进入默认精选探索路径 |
| 首页次动作 | `打开网页版简历` | Swiss CV 已可用 |
| 进入项目集 | `进入 AI 实验室` | 导航至项目世界 |
| 阅读项目 | `拆解这个项目` | 打开站内项目详情 |
| 外部项目 | `访问真实项目` | 仅 Link Record 已验证且内容为 final |
| 荣誉 | `查看荣誉档案` | 打开档案详情 |
| 个人经历 | `查看成长轨迹` | 打开 About/CV 对应位置 |
| 文章 | `读一篇思考` | 打开文章正文 |
| 视频 | `开始放映` | 媒体已就绪；否则改为 `查看视频摘要` |
| 照片 | `翻阅照片墙` | 打开相册或照片详情 |
| 联系 | `和我聊聊` | 已批准的真实联系渠道可用 |
| 恢复 | `回到首页`、`清除筛选`、`重新加载` | 与当前失败原因匹配，只给最有效的下一步 |

### 5.3 错误、空状态与确认

错误文案遵循“发生了什么 + 哪些内容仍安全 + 下一步”结构，并避免把系统责任推给访客。

- 推荐：`视频暂时没有加载成功。你仍可阅读摘要，或重新尝试播放。`
- 推荐：`没有符合这些条件的项目。清除筛选，看看全部实验。`
- 推荐：`这个链接还在等待本人确认，因此暂不开放。`
- 避免：`未知错误`、`操作非法`、`Oops!`、`即将上线`（没有后续信息时）。
- 仅在动作真实完成后确认，例如 `链接已复制`；打开邮件客户端不等于消息已发送，不得显示 `发送成功`。
- 空状态是内容状态而非错误，应说明正在发生的真实事情，并提供回到其他已完成内容的入口。

### 5.4 敏感表达与隐私

- 默认使用公开到城市级或更粗粒度的位置，不展示住址、宿舍、实时位置。
- 电话、私人邮箱、学号、证件号、证书二维码及第三方人物信息未经本人逐项批准不公开。
- 写比赛和竞争时聚焦目标、准备、结果与学习，不贬低对手或夸大主办方权威。
- 写挫折时本人拥有叙事权，不替本人虚构创伤、家庭、健康或经济经历。
- 照片出现他人时先确认授权；无法确认则遮挡、裁切或不发布。
- 联系入口不得暗示全天候回复、雇佣状态或合作承诺，除非本人明确确认。

### 5.5 中文、英文与长度预算

- **主语言：** 简体中文。英文用于世界副标题、学科/工具专名和少量视觉标记，不逐段机械重复翻译。
- **专名：** 产品、学校、赛事和工具使用官方写法；首次出现可采用 `中文名（English Name）`。
- **完整性：** 中文内容先达到完整可用；若未来提供英文版，应按整条旅程翻译，不发布中英混杂的半成品页面。
- **标点与数字：** 中文正文使用中文标点；项目指标保留单位和计算口径；日期优先 `YYYY-MM-DD` 或 `YYYY 年 M 月`，同类内容保持一致。

| 文案位置 | 推荐长度 |
|---|---:|
| 中文导航标签 | 2–6 个汉字 |
| 按钮 / CTA | 4–10 个汉字 |
| Hero 主标题 | 8–18 个汉字 |
| Hero 副标题 | 35–70 个汉字 |
| 页面标题 | 4–16 个汉字 |
| 卡片标题 | 不超过 20 个汉字 |
| 卡片摘要 | 45–90 个汉字 |
| 项目一句话结果 | 25–60 个汉字，指标必须有口径 |
| 空状态标题 | 6–16 个汉字 |
| 错误说明 | 25–70 个汉字，另配一个明确恢复动作 |

长度是编辑预算而非截断许可；超长时应重写或在正确层级展开，不用省略号隐藏关键事实。

## 6. 首轮占位写作边界

首轮可以撰写用于确认版式与语气的概念文案，但必须满足：

1. 所有人名、学校、奖项、年份、项目结果与联系方式使用显式变量或“待本人补充”，不创造拟真事实。
2. 概念项目使用明显的虚构名称和 `AI 生成概念示意 · 非真实项目` 标签；内容只验证结构，不计入本人能力证据。
3. 博客占位优先使用选题卡和提纲，不代替本人写一篇声称来自真实人生的心得。
4. 视频与照片占位只验证媒体比例、字幕、说明和浏览流程，不暗示画面人物就是本人。
